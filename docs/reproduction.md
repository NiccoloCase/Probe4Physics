# Reproducing experiments

The public release provides the probing implementation, scientific configurations,
and selected run manifests. It does not bundle the paper's measurement workbooks,
aggregated results, or workbook-based performance-plotting notebooks. Results
must be generated by running experiments on the required external assets.

## Prepare the inputs

1. Follow [data preparation](data.md) to obtain videos and create the grouped
   splits. The initialization commands write selection and split metadata under
   `data/splits/`; original videos are not included.
2. Obtain the backbone variants specified in `configs/backbones.yaml` from their
   upstream releases. Follow the upstream access and licensing terms.
3. Verify the retained configuration records:

```bash
python scripts/verify_release_inputs.py
python run.py health.layers strict_exit=true
```

`python run.py health` checks external asset readiness; a fresh checkout may
report missing videos, weights, or caches. That is separate from CPU unit tests.

## Extract, search, and evaluate

Follow [the experiment guide](experiments.md) for extraction, Optuna search,
fixed-configuration reruns, temporal controls, and random-label controls.
`probe.optuna.enabled=true` enables the existing search implementation. For a
selected configuration, keep Optuna disabled and use the recorded hyperparameters,
layer, seed, preprocessing, and split. The historical configuration and seed
records retain their original paths and hashes; inspect each run before execution.

```bash
python scripts/run_seed_manifest_row.py \
  --manifest results/seed_runs/seed_manifest_layerwise_main_linear_mlp_v1.csv \
  --probe linear --task-index 0 --dry-run
```

The manifest runner accepts execution-path overrides appended to the command.
Use the same resolved backbone settings for extraction and cache loading. Normal
training/evaluation writes checkpoints, predictions, metrics and summaries under
configurable `artifacts/` paths. Use `scripts/collect_seed_results.py` to aggregate
newly generated per-run artifacts into CSVs below `output/`. Its `--no-source-seed`
option excludes historical source-row metrics; see the experiment guide for the
seed-101/102 collection example and the additional seed-42 requirement.

## Relationship to the paper

| Paper content | Execution inputs and generated evidence |
| --- | --- |
| Main probing and depth comparisons (Table 1; Figures 1, 6–8) | Dataset/backbone/probe configs, selected layer records and main seed manifests; new evaluation metrics and per-layer summaries |
| Dataset construction (Tables 2–3) | `init.mvp` selection reports and grouped split metadata; original annotations/videos required |
| Model specification (Table 4) | `configs/backbones.yaml`, adapter metadata and `notebooks/parameter_counts.ipynb` |
| Search settings (Table 5) | Dataset YAML search spaces and retained selected configurations; defaults alone do not reconstruct every original search |
| Backbone-scale and matched-family comparisons (Figures 2–3, 9) | Backbone variants and the corresponding backbone-sweep/same-L manifests; new per-run metrics |
| Temporal and random-label controls (Tables 6–7; Figure 10) | Displacement/single-frame CLI commands and structured-random label configuration; trained probes and new evaluation outputs required |
| Compute (Tables 8–9) | New workload timing on the chosen hardware; complete original timing inputs and dedicated publication-table generators are not included |
| Illustrations (Figures 4–5) | Editorial artwork; Figure 5 is included as the README image, without its editable source layout |

This maps experiments to evidence; it does not provide publication-format plotting
or table generators for newly collected scores. The original performance analyses
remain on the development branch and depend on its historical measurement inputs.
Their exact workbook-based figure workflow is outside the public release.

## Model metadata notebook

The retained notebook inspects architecture/configuration metadata and needs no
performance workbooks. Execute it in a disposable snapshot:

```bash
python scripts/reproduce_notebooks.py \
  --output-dir output/reproduction/parameters \
  --notebooks parameter_counts
```

Use a fresh output directory. Executed source, exported DataFrames and `report.json`
are written there; the checked-in notebook is not overwritten. Parameter counts
have different scopes across backbones, as described by the notebook metadata.

## Limits

No full GPU extraction or training reruns were performed during release cleanup.
CPU fixtures validate pipeline behavior, not the independent recovery of every
published number. Original probe checkpoints and per-run outputs are not bundled;
historical attentive continuation requires its source checkpoint and training
summary, which cannot be supplied through output-path overrides alone. External
imports and missing original artifacts are not reconstructed from rounded paper
scores. The available configuration records do not guarantee complete end-to-end
reproduction of every experiment. The validation environment is recorded in
[validation-environment.json](validation-environment.json).
